## Сигурна инсталация

### Източник на дистрибуция (официален канал / checksum / подпис)

| Канал                | Описание                                                                                                                  |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| Официален GitHub     | [https://github.com/wiley68/jetcredit-ps9](https://github.com/wiley68/jetcredit-ps9) — клон `main` / release tag `v1.9.1` |
| Release артефакт     | ZIP/архив от GitHub Releases или клониран tag                                                                             |
| Проверка на версията | В архива: `config.xml`, `creditjet.php` → `1.9.1`; вижте и `CHANGELOG.md`                                                 |
| Checksum             | След изтегляне изчислете SHA-256 на архива и сравнете с публикуваната стойност в release бележките (ако е предоставена)   |

**Примерна проверка на checksum (Linux):**

```bash
sha256sum creditjet-1.9.1.zip
# Сравнете резултата с официално публикуваната стойност за release v1.9.1
```

**Не инсталирайте** модула от неофициални огледала, форуми или препратени архиви без проверка на произхода.

### Предварителни условия преди инсталация

1. Работещ магазин **PrestaShop 9.0.0 – 9.99.99**.
2. **PHP ≥ 8.1** с необходимите разширения за PrestaShop.
3. Активна поне една валута **BGN** или **EUR**.
4. Работеща конфигурация на **PrestaShop Mail** (SMTP препоръчително с TLS).
5. Административен достъп до Back Office (модули + конфигурация).
6. Файлови права за запис в `modules/` (или upload през BO).
7. Backup на базата данни и на директорията на магазина преди инсталация.
8. Магазинът е достъпен през **HTTPS**.

### Стъпки за инсталация

**Вариант A — през Back Office (препоръчително за търговци)**

1. Влезте в PrestaShop Back Office с администраторски акаунт.
2. Отидете на **Modules → Module Manager → Upload a module**.
3. Качете официалния ZIP на CreditJet.
4. Инсталирайте модула и потвърдете успешната инсталация.
5. Отворете конфигурацията на модула и попълнете задължителните полета (вижте „Сигурна конфигурация“).

**Вариант B — през файлова система / Git**

```bash
# От корена на PrestaShop магазина
cd /path/to/prestashop/modules

# Клониране на конкретен release tag
git clone --branch v1.9.1 --depth 1 https://github.com/wiley68/jetcredit-ps9.git creditjet

# Или разархивиране на официалния ZIP в modules/creditjet
# unzip creditjet-1.9.1.zip -d creditjet

# Права (пример; адаптирайте към вашия уеб потребител)
chown -R www-data:www-data creditjet
find creditjet -type d -exec chmod 755 {} \;
find creditjet -type f -exec chmod 644 {} \;
```

След това в Back Office: **Modules → Module Manager → CreditJet → Install**.

Инсталацията създава таблица `{prefix}jet_kop` и записва конфигурационни ключове в `ps_configuration`.

### Проверка след инсталация (health check)

1. Модулът е видим и със статус **Installed** в Module Manager.
2. Версията е **1.9.1** (`Modules → CreditJet` / `config.xml`).
3. В базата съществува таблица `{prefix}jet_kop`.
4. Конфигурационната страница на модула се отваря без грешки.
5. Попълнени са поне: **JET_ID** (идентификатор на магазина) и **JET_EMAIL**.
6. Модулът е активиран (`JET_STATUS_IN = On`), ако искате бутоните да се показват.
7. На продуктова страница / кошница / чекаут (според настройките) се визуализира кредитният калкулатор.
8. Тестова AJAX калкулация връща JSON успех (без CSRF / Forbidden грешки).
9. Тестова заявка (в непродукционна среда) генерира имейл до администратора и към адреса в `JET_EMAIL`.

### Поддържани ОС / runtime версии

| Компонент  | Изискване                                                               |
| ---------- | ----------------------------------------------------------------------- |
| Платформа  | PrestaShop **9.0.0 – 9.99.99**                                          |

| ОС         | Всяка ОС, поддържана от PrestaShop 9 и PHP (типично Linux в production) |
| Уеб сървър | Apache / Nginx (или еквивалент)                                         |
| База данни | MySQL / MariaDB според изискванията на PrestaShop 9                     |
| Валути     | Активна **BGN** и/или **EUR**                                           |

### Минимален хардуер / ресурси

Модулът няма отделни хардуерни изисквания над тези на хост средата PrestaShop.

- **CPU / RAM / диск:** според официалните минимуми на PrestaShop 9 за очаквания товар.
- **Допълнителен overhead:** незначителен (локални PHP изчисления, AJAX, записи в DB/конфигурация).
- **Отделен сървър / GPU / контейнер:** не се изисква.

### Мрежови изисквания

| Посока              | Изискване                      | Предназначение                                       |
| ------------------- | ------------------------------ | ---------------------------------------------------- |
| Входящ HTTPS        | TLS към публичния магазин      | Клиентски заявки и AJAX към модула                   |
| Изходящ имейл       | Работещ PrestaShop Mail / SMTP | Изпращане на заявки към търговеца и ПБ Лични Финанси |
| Директен банков API | **Не се изисква**              | Няма изходящи HTTP API повиквания към банка          |

Не са нужни допълнителни входящи портове извън стандартните на уеб сървъра (443/80) и вече използваните от PrestaShop услуги.

### Зависимости от трети страни

| Зависимост               | Тип                         | Роля                                          |
| ------------------------ | --------------------------- | --------------------------------------------- |
| PrestaShop 9.x           | Платформа                   | Хост система                                  |
| PHP ≥ 8.1                | Runtime                     | Изпълнение                                    |
| MySQL / MariaDB          | Persistence                 | Конфигурация и промо таблица                  |
| PrestaShop Mail / SMTP   | Комуникация                 | Доставка на заявки                            |
| ПБ Лични Финанси         | Бизнес партньор             | Обработка на кредитните заявки извън магазина |

Dev зависимости (напр. CycloneDX) **не** са нужни за продукционна работа.

## Изисквани права

### Privilege за инсталация

| Право                                             | Защо                                                     |
| ------------------------------------------------- | -------------------------------------------------------- |
| PrestaShop администратор (Modules)                | Инсталация / деинсталация / конфигурация през BO         |
| Запис в `modules/creditjet/`                      | Разполагане на файловете на модула                       |
| CREATE/ALTER върху DB (чрез PrestaShop installer) | Създаване на `{prefix}jet_kop` и конфигурационни ключове |

### Privilege за runtime

| Право                                                 | Защо                     |
| ----------------------------------------------------- | ------------------------ |
| Изпълнение на PHP като уеб потребител на PrestaShop   | Front и admin контролери |
| Четене/запис в `ps_configuration` и `{prefix}jet_kop` | Настройки и промо схеми  |
| Изпращане на имейли чрез PrestaShop Mail              | Предаване на заявки      |
| Сесийни / CSRF токени на PrestaShop                   | Защита на AJAX endpoints |

### Какво **не** е нужно (least privilege)

- Root / sudo на ОС за ежедневна работа на модула.
- Отделен cloud IAM role / service account.
- Privileged Docker capabilities (`SYS_ADMIN`, host network и др.).
- Директен достъп на модула до файловата система извън PrestaShop.
- Постоянни API ключове към банкова система (модулът не ги използва).
- Публичен write достъп до `documents/`, `sql/`, `src/` и други вътрешни директории (защитени с `index.php`).

Конфигурацията трябва да се променя **само** от администратори на магазина.

## Сигурна конфигурация

### Задължителни настройки за сигурност

1. Магазинът работи през **HTTPS**.
2. Попълнете **JET_ID** — идентификатор на магазина, договорен с банката.
3. Попълнете **JET_EMAIL** — адрес(и) за получаване на заявки (напр. `pf-online.shop@postbank.bg` и/или вътрешен адрес; множество адреси със запетая).
4. Активирайте модула (`JET_STATUS_IN`) едва след проверка на идентификатора и имейла.
5. Уверете се, че PrestaShop Mail изпраща успешно (без отворен relay).
6. Ограничете Back Office доверени администратори; използвайте силни пароли / 2FA на ниво PrestaShop/хостинг, ако е налично.

### Препоръчителни hardening стъпки

- Дръжте PrestaShop, PHP и модула актуални.
- Забранете directory listing; запазете `index.php` в поддиректориите на модула.
- Не оставяйте debug / dev инструменти в production (`vendor` dev пакети не са нужни runtime).
- Тествайте кредитните заявки първо в staging.
- Ограничете SMTP само към нужните получатели.
- Редовно преглеждайте промо схемите в `{prefix}jet_kop`.
- Не публикувайте вътрешни идентификатори и конфигурация в публични репозиториуми на клиента.

### Конфигурационни файлове / ключове / secrets management

| Елемент                         | Къде                                         | Бележка                                  |
| ------------------------------- | -------------------------------------------- | ---------------------------------------- |
| Бизнес настройки                | `ps_configuration` (`JET_*`)                 | Управление през BO формата на модула     |
| Промо схеми                     | `{prefix}jet_kop`                            | Админ UI / DB                            |
| Secrets / API ключове на модула | **Няма**                                     | Модулът не съхранява банкови API ключове |
| SMTP credentials                | Конфигурация на PrestaShop (не на CreditJet) | Пазете ги според хостинг практиките      |

Модулът **не** изисква `.env` файл със секрети за нормална работа.

## Криптография и защита на комуникациите

> В шаблона на CRA формата тази секция често е отделна; тук са покрити точките за TLS, данни в покой и ключове. За модул от тип PrestaShop plugin повечето контроли са на ниво хост платформа.

### TLS версии / cipher suites

- **Приложимо на ниво хост (уеб сървър / reverse proxy), не в кода на модула.**
- Изисквайте HTTPS към магазина.
- Препоръка: TLS **1.2+** (предпочитано TLS 1.3); деактивирайте SSLv3 / TLS 1.0 / 1.1.
- Cipher suites: следвайте актуалните hardening насоки на вашия уеб сървър / CDN.
- SMTP към mail gateway: използвайте TLS/STARTTLS, когато доставчикът го поддържа.

### Криптиране на данни в покой

- **Неприложимо като отделна функция на модула.** CreditJet не прилага собствено disk encryption.
- Данните се съхраняват в DB на PrestaShop; разчитайте на криптиране на ниво хостинг/диск (LUKS, cloud volume encryption и т.н.), ако е изискване на вашата среда.
- В имейл payload-а се предават ПДн (име, телефон, ЕГН и др.) — каналът трябва да е защитен (SMTP TLS) и достъпът до пощенските кутии — ограничен.

### Управление на ключове

- **Неприложимо за CreditJet** — модулът не управлява криптографски ключове, сертификати или API secrets.
- TLS сертификатите и SMTP credentials се управляват от хостинга / PrestaShop, не от този модул.

## Журналиране

### Какви събития се логват

CreditJet **няма собствен централизиран security audit log**. Разчита на:

| Събитие                               | Къде се вижда                                                                                     |
| ------------------------------------- | ------------------------------------------------------------------------------------------------- |
| Успешни/неуспешни имейл изпращания    | PrestaShop Mail / SMTP логове на сървъра                                                          |
| CSRF / non-AJAX отказ                 | HTTP отговор (`Forbidden` / `CSRF protection`) — може да е в access/error логовете на уеб сървъра |
| Създадени поръчки при кредитна заявка | Стандартни PrestaShop order записи                                                                |
| Промени в конфигурацията              | Обикновено през PrestaShop admin (ако е активиран admin logging)                                  |

Санитизацията на bank payload (`sanitizeBankField`) намалява риска от счупен формат, но **не** създава отделен log запис.

### Къде се съхраняват логовете

- Уеб сървър: access/error logs на хоста.
- PrestaShop: системни/mail логове според конфигурацията на платформата.
- Модулът не пише отделни файлове в `modules/creditjet/logs/`.

### Retention и защита на логове

- Определете retention според хостинг политиката и GDPR (логовете може да съдържат ПДн от заявки/имейли).
- Ограничете достъпа до логовете само до администратори/ops.
- Не комитвайте логове в git и не ги правете публично достъпни през уеб.

## Процедура за обновяване

1. **Проверка за налични обновявания**
   - Следете GitHub Releases / `CHANGELOG.md` в [jetcredit-ps9](https://github.com/wiley68/jetcredit-ps9).
   - Сравнете инсталираната версия (`config.xml` / `creditjet.php`) с последната публикувана.
2. **Предварителен backup / staging**
   - Backup на DB и `modules/creditjet/`.
   - Приложете обновяването първо на staging копие на магазина.
3. **Прилагане на patch / release**
   - Инсталирайте новия ZIP през BO **или** заменете файловете с официалния tag/release.
   - Не смесвайте файлове от различни версии.
   - След обновяване изчистете PrestaShop cache при нужда.
4. **Валидация след обновяване**
   - Проверете версията и `CHANGELOG.md`.
   - Health check (калкулатор, CSRF, тестова заявка).
   - Потвърдете, че `JET_*` настройките са запазени.

При security release приложете обновяването възможно най-бързо след успешен staging тест.

## Докладване на уязвимости

### Канал за докладване

Изпратете доклад на **`home@avalonbg.com`** (копие до `ilko.iv@gmail.com` при технически детайли).  
Може да използвате и частен (confidential) канал през GitHub Security Advisories на репозиториума, ако е активиран.

**Моля, не** публикувайте експлойти в публични issues преди да е наличен fix.

### Каква информация да включат

- Засегната версия на модула и на PrestaShop / PHP.
- Описание на уязвимостта и impact (confidentiality / integrity / availability).
- Стъпки за възпроизвеждане (PoC без разрушителни действия върху чужди системи).
- Очакван vs реален резултат.
- Евентуални логове, скрийншоти, предложена mitigation.

### Очаквано потвърждение и процес

## Период на поддръжка

### Продължителност на security support

- Текущата major линия за PrestaShop 9 (`9.x`) се поддържа с security/bugfix обновявания, докато модулът официално поддържа тази платформа.
- За версия **1.9.1** security support следва lifecycle на клона PrestaShop 9 и активната продуктова линия CreditJet.
- По-стари major линии (напр. при бъдещ PrestaShop 10 fork) могат да бъдат обявени като EOL отделно.

- `CHANGELOG.md` в дистрибуцията и в GitHub.

## Поведение след край на поддръжката

### Какво спира (patching, updates, cloud features)

След обявен **End of Support (EOS) / End of Life (EOL)** за дадена версия/линия:

- Спират security patch-и и функционални обновявания за тази версия.
- Спира официална поддръжка за инциденти.
- Няма cloud features на самия модул (неприложимо) — но интеграцията с банката чрез имейл може да продължи да „работи“ технически без да е поддържана.

### Препоръки за миграция

1. Надградете до последната поддържана версия на CreditJet.
2. Осигурете съвместим PrestaShop / PHP според новата версия.
3. Тествайте в staging, после production по „Процедура за обновяване“.
4. Ако платформата ви е EOL — мигрирайте магазина към поддържан PrestaShop преди/заедно с модула.

### Рискове при продължаване на употреба

- Неадресирани уязвимости в модула или в зависимостите на платформата.
- Несъвместимост с бъдещи промени при банковия имейл формат.
- Регулаторни / CRA рискове при използване на неподдържан продукт с ПДн.
- Липса на официална помощ при инциденти.

## Известни ограничения

| Ограничение                                                                | Mitigation                                                                                                                                         |
| -------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| Няма директен банков API; заявките минават по имейл с `;`-delimited формат | Поддържайте работещ SMTP TLS; използвайте `sanitizeBankField` (вградена от 1.9.1); тествайте payload-а с банката                                   |
| Модулът няма собствен centralized audit log                                | Разчитайте на PrestaShop/web/mail логове; активирайте admin logging на платформата                                                                 |
| ПДн (вкл. ЕГН) се предават в имейл към банка/търговец                      | Ограничете достъпа до пощенски кутии; минимизирайте копията; спазвайте GDPR                                                                        |
| Сигурността зависи силно от hardening на PrestaShop / хостинга             | Поддържайте платформата актуална; HTTPS; least privilege за админи                                                                                 |
| CSRF/AJAX защитата разчита на PrestaShop token                             | Не изключвайте стандартните session/cookie защити на PrestaShop; не кеширайте HTML с токени агресивно по начин, който ги споделя между потребители |
| Няма вграден rate limiting на front endpoints                              | Приложете WAF / rate limit на уеб сървър / CDN при нужда                                                                                           |
| Dev зависимости / SBOM инструменти не са runtime security control          | Не разчитайте на тях в production; използвайте ги в CI за прозрачност на доставките                                                                |
